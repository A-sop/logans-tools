# RR-010 step 1: Watchman — Amendment 2 (fix round 2, 1 Nov 2026)

Committed on its own, after Amendment 1 and before any further code on this round. It does not
change the watchman's purpose; it closes five gaps Dept13 / fix-round-2 found in the built
acceptance. Dept13 checks the build against AC1–AC9 as amended by Amendment 1 and this file.
Verdict format: exact first line `Dept13 PASS|FAIL @<full 40-hex sha>` (no CONDITIONAL).

## A6 (AC1 grants, A5 rule 6) CREATEROLE creator membership and full footprint
On PostgreSQL 16+, a non-superuser CREATEROLE owner (Neon `neondb_owner` in prod) who runs
`CREATE ROLE dabos_watchman` is auto-granted membership in that role `WITH ADMIN OPTION`. Guard 4d
must not count that single implicit grant as a forbidden membership. It still refuses every
membership *of* `dabos_watchman` (the role as `member`) and every other membership *in* it
beyond that creator grant.

Guard 4 also matches the status-digest grants standard (logans-tools #61 guard 3c–3g): after the
GRANTs, inside the same transaction, refuse unless the role's whole footprint is exactly the
intended privileges — ownership of nothing; no default privileges for or by the role; no
EXECUTE (or other) grants on functions/types/languages/tablespaces/foreign objects/large
objects/parameters; no unintended schema or database ACL to the role; and effective privileges
that reach the role via PUBLIC are refused for: privileges on other tables/sequences, CREATE on
schema `public`, and CREATE or TEMP on the database (when those appear as ACL entries for
PUBLIC). PUBLIC's PostgreSQL defaults that are not materialised in `datacl`/`nspacl` are not
invented as failures. Tests cover each refusal.

## A7 (AC2, AC3a) Sender spoofing
- `from_agent = 'logan'` is refused: a table CHECK on `agent_inbox`, and the `dabos-inbox send`
  CLI / `validateSend`. Logan's words reach agents only as an LDW relay
  (`from_agent = 'ldw'` with reason code `logan_order` or `logan_decision`). The gate may still
  wake on a historical `from_agent = 'logan'` row if one exists; new inserts cannot create one.
- `watchman` is dropped from the CLI sender allowlist. Only the watchman script inserts
  `from_agent = 'watchman'` (failure rows); agents never do.
- Runbook (`src/docs/dabos/agent-inbox.md`): note that `ldw` as a sender cannot be verified —
  any holder of an insert path can claim it. Authority of an LDW relay still rests on process,
  not on cryptographic proof of sender.

## A8 (AC3, A3) Failed `deadline_today` claim
When `urgency_claim = 'deadline_today'` and `deadline_at` is set but does **not** fall on today's
Europe/Berlin date, the claim fails its test: the row is batched with note
`downgrade:deadline_not_today` (unless some other wake rule applies on the facts). Missing
`deadline_at` stays `downgrade:no_deadline_at`. Tests cover both.
