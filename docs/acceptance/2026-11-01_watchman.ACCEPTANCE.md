## Purpose
A script gatekeeper on ln02. It is NOT an LLM and costs no Grok Bot tokens. For every agent-to-agent message it decides deterministically whether the recipient is woken now or the item is added to a batch.

## AC1 Inbox (Neon prod: project red-moon-24328019, branch br-damp-tree-b1h8mksl)
- First check read-only whether the existing `tasks` table (in/pending/out baskets, dedupe keys) can serve. Record the finding in the PR.
- If it cannot, add table `agent_inbox` with: id, created_at, from_agent, to_agent, subject, body, urgency_claim (none|urgent|blocking|deadline_today), urgency_reason, deadline_at, blocks (who/what is blocked), dedupe_key UNIQUE, status (queued|delivered|superseded), batch_id, delivered_at.
- Delivered as a dated SQL file under scripts/dabos/sql/ with guards that abort on mismatch, an idempotent re-run and an undo that targets only this PR's objects. Applied later, whole, as one transaction (psql -1 -f). NOT applied in the build session.

## AC2 Writing
- Agents insert rows via a small documented INSERT runnable through the Neon tool, and via a CLI helper `dabos-inbox send`.
- Documented rule: agents never put secrets, DVAG client data or Whop order data in subject/body.

## AC3 Gate rules (deterministic, unit-tested)
Wake NOW only if:
- (a) sender is Logan, or LDW relaying a Logan decision or order;
- (b) urgency_claim=blocking AND `blocks` names Logan or an agent that is actually waiting;
- (c) deadline_at is today (Europe/Berlin) and the item is not already done;
- (d) urgency_claim=urgent with a non-empty urgency_reason matching an allowlist: prod down, data loss, security, deadline within 6 h.
- A claim missing its reason is downgraded to batch and logged.
- Everything else is batched. FYIs, acknowledgements and thanks are dropped or folded in, never woken for.
- Duplicates go by dedupe_key; a newer item on the same key supersedes the older (status=superseded).

## AC4 Batching
- Per recipient, flush at most once every 2 hours, only if non-empty, only between 07:00 and 23:00 Europe/Berlin.
- An urgent wake also flushes that recipient's queued batch with it (one wake sees everything).

## AC5 Delivery
- Each agent has ONE Grok Bot routine with a webhook trigger. Watchman POSTs {to_agent, batch_id, item_ids, reason} to that agent's webhook URL with its sender key.
- URLs and keys live in ln02 ~/.config/dabos/watchman.env (chmod 600), placed by Logan from each routine panel. The script never logs them.
- The routine reads its rows, marks them delivered, and acts.
